## 1. Overview

EchoMinutes is a native macOS utility app that runs quietly in the menu bar, **automatically detects when a voice/video call starts** in any communication app (Microsoft Teams, Zoom, WhatsApp, Google Meet in a browser, Slack Huddles, FaceTime, Webex, Discord, etc.), **records both sides of the conversation**, produces a **speaker-labelled transcript**, and generates an **AI meeting summary** (key points, decisions, action items).

The LLM / speech-to-text provider is **bring-your-own-key (BYOK)**: the user enters their API key(s) in the app's Settings UI. A fully local (offline) mode is also supported.

### 1.1 Goals

1. Zero-touch capture: the user should never miss recording a meeting because they forgot to press a button.
2. Capture **both** the user's microphone and the remote participants' audio, cleanly, without virtual audio drivers.
3. Accurate transcript with timestamps and speaker separation.
4. Useful, structured summaries generated by the user's chosen LLM provider.
5. Privacy-first: everything stored locally; data only leaves the Mac when the user picks a cloud provider.

### 1.2 Non-goals (v1)

- No meeting "bot" that joins calls as a participant.
- No cloud sync / team sharing server (export only in v1).
- No video/screen recording.
- No Windows/Linux/iOS versions.

### 1.3 Target user & product positioning

- **Primary user: Tanim (single user).** EchoMinutes is a personal productivity utility built for my own daily calls across Teams, Zoom, WhatsApp, etc.
- Built to product quality (signed, notarized, onboarding, settings) so it could later be shared, but v1 has **no accounts, licensing, payments, or backend**.
- Design assumption: one user, one Mac, all data local.

### 1.4 Name

**EchoMinutes** — "echo" for capturing every voice in the call, "minutes" for meeting minutes. Short, descriptive, works as a menu bar label and bundle ID (`com.tanimkabir.echominutes`).

Alternatives considered: *CallScribe*, *HuddleNotes*, *MinuteTaker*, *Murmur*, *Recapify*.

> Before publishing anywhere public, check App Store / trademark / domain availability for the name.

## 5. Functional requirements

### 5.1 Meeting auto-detection

**FR-DET-01 — App monitoring.** The app shall observe launched/terminated applications using `NSWorkspace` notifications and keep a live list of running meeting apps from the watch list.

**FR-DET-02 — Microphone-in-use signal (primary trigger).** The app shall detect when the default (or any) input device becomes active using Core Audio:
- `kAudioDevicePropertyDeviceIsRunningSomewhere` on input devices (any process using the mic).
- On macOS 14.4+, enumerate audio process objects (`kAudioHardwarePropertyProcessObjectList`) and read `kAudioProcessPropertyIsRunningInput` / `kAudioProcessPropertyBundleID` to identify **which app** is using the microphone.

**FR-DET-03 — Meeting start rule.** A meeting is considered started when **all** of:
1. A watched app (or a browser with a matching meeting tab) is the process using the microphone, **and**
2. The condition holds continuously for a debounce period (default **5 s**, configurable 2–30 s) — avoids false triggers from voice notes or mic tests.
3. Optional secondary signals raise confidence: app is also producing audio output; window title contains "Meeting"/"Call"/participant names; a calendar event is currently active (§5.8).

**FR-DET-04 — Meeting end rule.** A meeting is considered ended when the triggering app stops using the microphone **and** stops producing output for a grace period (default **15 s**), or the app quits. Grace period prevents splitting when the user briefly mutes or the app re-negotiates devices.

> Note: when the user mutes in Teams/Zoom, those apps typically keep the input device open, so mute should not end the session. Must be validated per app.

**FR-DET-05 — Start behaviour (user-configurable per app):**
- **Auto-record (default for all watched apps)** — recording starts automatically as soon as the meeting-start rule is met, with no prompt. A notification confirms it: "Recording Zoom call… [Stop] [Discard]", and the menu bar icon turns red.
- **Ask first** — optional per app: notification with [Record] [Ignore] buttons; auto-dismiss after 20 s → configurable default action.
- **Never** — ignore this app.

**FR-DET-05a — Safety net for auto-record.** Because recording starts without a prompt:
- The "Discard" action is available for the first 60 s from the notification and at any time from the menu bar.
- Exclusion rules (FR-DET-08) and per-app "Never" are the primary way to prevent unwanted recordings (e.g., personal WhatsApp calls).

**FR-DET-06 — Manual override.** Global hotkey (default `⌃⌥⌘R`) and menu bar item "Start recording now" to record any audio manually, selecting source app(s).

**FR-DET-07 — Concurrent calls.** If a second meeting app starts a call while one is being recorded, keep recording the first and show a notification offering "Switch to <app>" (no automatic second recording).

**FR-DET-08 — Exclusion rules.** Never auto-record when:
- App is on the excluded list.
- Current time is within user-defined "private hours".
- (Optional) Focus mode matches a configured Focus.

### 5.2 Audio capture

**FR-AUD-01 — Dual-track recording.** Record two separate tracks per session:
- **Mic track** — user's microphone via `AVAudioEngine` / AVCaptureSession on the selected input device.
- **System track** — the meeting app's output audio via **Core Audio Process Taps** (`AudioHardwareCreateProcessTap` + aggregate device, macOS 14.2+), scoped to the meeting app's process(es) only, so notifications/music from other apps are **not** recorded.
- Fallback: ScreenCaptureKit audio capture (`SCStreamConfiguration.capturesAudio`, excluding own process) when process tap is unavailable.

**FR-AUD-02 — No virtual drivers.** The app must not require BlackHole, Loopback, or any kernel/driver install.

**FR-AUD-03 — Headphones & speakers.** Capture must work whether the user uses AirPods/headphones or built-in speakers. With speakers, apply echo handling (Voice Processing I/O or post-process cancellation of the system track from the mic track) to reduce duplicate transcription.

**FR-AUD-04 — Device changes.** Handle hot-swapping input/output devices (e.g., AirPods connected mid-call) without stopping the recording; log a marker in the session.

**FR-AUD-05 — Format & storage.**
- Capture at 48 kHz; store per-track AAC (`.m4a`, 64–96 kbps mono) or Opus; also produce a mixed stereo/mono playback file.
- Write in rolling chunks (e.g., every 30 s) so a crash loses at most one chunk (see §7.4).
- Estimated size: ~45 MB/hour per track at 96 kbps.

**FR-AUD-06 — Controls.** Pause / Resume / Stop / Discard / Add bookmark (with optional note) from the menu bar, floating mini-widget, and hotkeys.

**FR-AUD-07 — Live level meters** for mic and system track in the recording widget, plus a warning if one track is silent for > 60 s ("No audio from Zoom detected — check permissions").

### 5.3 Transcription (STT)

**FR-STT-01 — Provider options:**

| Mode | Engines | Notes |
|---|---|---|
| Local (default) | WhisperKit (Core ML) / whisper.cpp; Apple `SpeechAnalyzer`/`SFSpeechRecognizer` on supported OS | Offline, free, uses Apple Silicon Neural Engine |
| Cloud (BYOK) | OpenAI (Whisper / gpt-4o-transcribe), Deepgram, AssemblyAI, Google Speech-to-Text, Azure Speech, Groq Whisper | Requires user key; better diarization on some |

**FR-STT-02 — Live transcript.** While recording, show a near-real-time transcript (target latency ≤ 5 s on local engine on Apple Silicon) in the floating window. Live transcript can be lower-accuracy; a final pass runs after the meeting.

**FR-STT-03 — Final transcript.** After the meeting ends, run a high-accuracy pass over full tracks; replace the live transcript.

**FR-STT-04 — Speaker attribution.**
- Mic track segments → labelled **"Me"** (user's display name from Settings).
- System track segments → diarized into "Speaker 1, Speaker 2…" (local diarization model e.g. pyannote-style Core ML model, or provider diarization).
- User can rename speakers; renames propagate across the session (and optionally to future sessions via voice-print matching — P2).

**FR-STT-05 — Language.** Auto-detect language; allow forcing a language per app/session. Must support at least English and Bengali; mixed-language (code-switching) handled best-effort.

**FR-STT-06 — Custom vocabulary.** User-defined glossary (names, product terms like "JazzTicketing") passed as prompt/hints to the STT engine.

**FR-STT-07 — Timestamps.** Every segment has start/end timestamps; clicking a segment seeks the audio player.

### 5.4 AI summary & insights (LLM)

**FR-LLM-01 — Providers (BYOK).**

| Provider | Auth fields in UI |
|---|---|
| Anthropic (Claude) | API key, model |
| OpenAI | API key, model, optional org ID |
| Google Gemini | API key, model |
| Azure OpenAI | Endpoint, deployment name, API key, API version |
| OpenRouter | API key, model |
| OpenAI-compatible (custom) | Base URL, API key (optional), model |
| Ollama / LM Studio (local) | Base URL (default `http://localhost:11434`), model |

**FR-LLM-02 — Summary output (default template):**
1. Title (auto-generated, editable)
2. TL;DR (3–5 sentences)
3. Key discussion points
4. Decisions made
5. Action items — *owner, task, due date (if mentioned)*, with a checkbox
6. Open questions / risks
7. Follow-ups / next meeting

Output requested as structured JSON from the LLM, validated against a schema, then rendered; fall back to Markdown on schema failure.

**FR-LLM-03 — Templates.** Built-in templates: General, Daily Stand-up, 1:1, Client/Sales Call, Interview, Sprint Planning, Retro. User can create/edit templates (prompt + section list). Template can be auto-selected by rule (e.g., app = Zoom and title contains "Stand-up").

**FR-LLM-04 — Long meetings.** For transcripts exceeding the model context window, use chunked map-reduce summarisation; show progress.

**FR-LLM-05 — Auto vs manual.** Setting: generate summary automatically when transcript completes (default on), or on demand via "Summarize" button. "Regenerate" with a different template/model is always available.

**FR-LLM-06 — Ask the meeting (chat).** Per-session Q&A panel answering questions grounded in that transcript with timestamp citations. (P1) Cross-meeting Q&A over the whole library (P2).

**FR-LLM-07 — Cost & token visibility.** Show estimated token count and cost before/after each LLM call (using a configurable price table); monthly usage counter in Settings.

**FR-LLM-08 — Error handling.** Invalid key, rate limit, network failure, or quota errors are shown clearly with a "Retry" action; the transcript is never lost because a summary fails.

### 5.5 API key management (Settings UI)

**FR-KEY-01** — Settings → **Providers** tab lists each provider with: Enable toggle, key field (secure text, masked `sk-…a9F2`), model dropdown, base URL (where applicable), and **"Test connection"** button.

**FR-KEY-02** — Keys are stored **only in the macOS Keychain** (`kSecClassGenericPassword`, access group of the app, `kSecAttrAccessibleWhenUnlocked`). Never written to disk, logs, crash reports, or exported files.

**FR-KEY-03** — Separate default selections for **Transcription provider** and **Summary provider** (e.g., local Whisper + Claude for summary).

**FR-KEY-04** — Model list fetched from provider's models endpoint when available; otherwise free-text model name.

**FR-KEY-05** — "Remove key" deletes from Keychain. Optional Touch ID prompt to reveal a stored key.

**FR-KEY-06** — If a cloud provider is selected but no valid key exists, the app falls back to local mode (if enabled) and shows a non-blocking banner.

### 5.6 Meeting library & session detail

**FR-LIB-01 — Library list** (main window sidebar): sessions grouped by Today / This week / Earlier; each row shows title, app icon, date/time, duration, status (Recording, Transcribing, Summarizing, Ready, Failed).

**FR-LIB-02 — Filters & search:** by app, date range, tag, speaker, has-action-items; full-text search across titles, transcripts, summaries and notes (SQLite FTS5), results highlight and jump to timestamp.

**FR-LIB-03 — Session detail view:**
- Header: title (editable), app, date, duration, participants/speakers, tags.
- Audio player: play/pause, speed (0.5×–2×), skip ±15 s, waveform with bookmarks and speaker colour bands; per-track mute (Me / Others).
- Tabs: **Summary** | **Transcript** | **Action Items** | **Notes** | **Ask**.
- Transcript: auto-scroll follows playback; click-to-seek; inline edit text; copy selection.
- Action items: checkable, editable; "Copy as checklist".
- Notes: user's free-form Markdown notes taken during/after the meeting.

**FR-LIB-04 — Export:** Markdown, PDF, DOCX, TXT, SRT/VTT (transcript), audio (M4A/WAV). Choose sections to include. "Copy summary to clipboard" one-click.

**FR-LIB-05 — Delete:** delete session (audio + text) with confirmation; "Delete audio only, keep transcript & summary" option.

**FR-LIB-06 — Detection config list** (Settings → Detection) shows watched apps with per-app mode (Auto / Ask / Never), debounce/grace overrides, and an "Add app" picker. Detection rules ship as a bundled JSON that can be updated with app updates.

### 5.7 Menu bar & recording UI

- **Menu bar icon states:** Idle (outline), Monitoring call (dot), Recording (red, with elapsed time), Processing (spinner).
- **Menu bar dropdown:** current status, Start/Stop/Pause, Recent 5 meetings, Open Library, Settings, Quit.
- **Floating mini-widget** (optional, draggable, always-on-top): timer, levels, live transcript toggle, bookmark, stop.
- **Notifications** (UserNotifications): call detected, recording started/stopped, transcript ready, summary ready, errors.

### 5.8 Calendar integration (P1)

- Optional EventKit access to read current event (title, attendees, notes).
- When a meeting starts during an event, auto-title session with the event name and pre-fill participant names to help speaker labelling.
- Never writes to the calendar.

### 5.9 Integrations & sharing (P2)

- Send summary via email (mailto / share sheet), copy to Apple Notes, Notion, Confluence, Jira (create tasks from action items), Slack webhook.
- Webhook on "summary ready" with JSON payload.

### 5.10 Consent & compliance

**FR-CMP-01** — First-run screen explaining that recording laws vary (one-party vs all-party consent) and that the user is responsible for informing participants.

**FR-CMP-02** — Optional "consent reminder" notification when recording starts, with a one-click "Copy consent message" (e.g., *"Heads-up: I'm recording this call for note-taking."*) to paste into meeting chat.

**FR-CMP-03** — Recording indicator always visible while recording; the app never records invisibly.

**FR-CMP-04** — The app relies on macOS's own mic indicator (orange dot) and audio-capture privacy indicator; it must not attempt to hide them.

## 7. Non-functional requirements

### 7.1 Platform
- Minimum: **macOS 14.4 Sonoma** (Core Audio process taps + process object properties). Target latest macOS.
- Apple Silicon first-class; Intel supported with cloud STT recommended (local Whisper may be slow).

### 7.2 Performance
- Idle monitoring: < 1% CPU, < 80 MB RAM.
- Recording (no live transcript): < 5% CPU on M1.
- Local final transcription: ≤ 0.3× real-time on M1 with a "small/turbo" model (1 h meeting → ≤ 18 min); configurable model size.
- Detection-to-recording latency: ≤ debounce + 1 s. Audio from the start of the debounce window should be retained via a short **pre-roll buffer** (rolling 10 s) so the first words aren't lost.

### 7.3 Privacy & security
- All data stored locally in `~/Library/Application Support/EchoMinutes/`.
- Optional encryption at rest (AES-GCM with a key in Keychain).
- No telemetry by default; opt-in anonymous crash reports with no transcript/audio/key content.
- Clear indicator in UI of where data is sent for each session ("Transcribed locally · Summarized by Anthropic").
- Per-app setting "Local processing only" (e.g., force local for WhatsApp personal calls).

### 7.4 Reliability
- Chunked writes; on crash/power loss, the next launch detects incomplete sessions and offers **Recover**.
- Processing jobs (transcribe/summarize) run in a persistent queue that resumes after relaunch.
- Low-disk guard: warn at < 2 GB free, stop recording safely at < 500 MB.

### 7.5 Retention
- Settings: keep audio for N days (7/30/90/forever) — transcripts & summaries kept independently.
- Storage usage view with "clean up" actions.

### 7.6 Accessibility & localisation
- Full VoiceOver support, keyboard navigation, Dynamic Type-friendly layouts, light/dark mode.
- UI in English v1; strings externalised for localisation (Bengali planned).

### 8.1 Tech stack
- **Language/UI:** Swift 6, SwiftUI (+ AppKit where needed for menu bar/panels), Observation framework.
- **Audio:** Core Audio (process taps, aggregate devices), AVFoundation, ScreenCaptureKit (fallback).
- **STT local:** WhisperKit (Core ML) or whisper.cpp; Apple Speech framework as option.
- **Diarization:** Core ML speaker-embedding model + clustering (or provider diarization).
- **LLM:** thin provider abstraction (`LLMProvider` protocol: `complete`, `stream`, `listModels`, `testConnection`); HTTP via URLSession; streaming via SSE.
- **Persistence:** GRDB.swift (SQLite + FTS5).
- **Updates:** Sparkle 2.
- **Exports:** Markdown native; PDF via WebKit/PDFKit render; DOCX via a lightweight generator.

### 8.2 Key interfaces (sketch)

```swift
protocol TranscriptionEngine {
    var id: String { get }
    var supportsStreaming: Bool { get }
    func transcribe(audio: URL, options: STTOptions) async throws -> Transcript
    func stream(_ buffers: AsyncStream<AVAudioPCMBuffer>, options: STTOptions) -> AsyncThrowingStream<TranscriptSegment, Error>
}

protocol LLMProvider {
    var id: String { get }
    func testConnection() async throws
    func listModels() async throws -> [String]
    func complete(_ request: LLMRequest) async throws -> LLMResponse
    func stream(_ request: LLMRequest) -> AsyncThrowingStream<String, Error>
}
```

### 8.3 Session state machine

```
Idle → CallDetected → (Ask: Prompted) → Recording ⇄ Paused → Finalizing
     → Transcribing → Summarizing → Ready
Any state → Failed (with retry) │ Recording/Paused → Discarded
```

## 10. Settings structure

1. **General** — launch at login, your name (for "Me"), default language, hotkeys, mini-widget on/off.
2. **Detection** — watched apps & modes, browser detection on/off, debounce/grace, private hours, concurrent-call behaviour.
3. **Recording** — input device, audio quality, echo handling, pre-roll, save location.
4. **Transcription** — engine (local/cloud), local model size (download manager), language, custom vocabulary, diarization on/off.
5. **AI Summary** — provider & model, auto-summarize, default template, templates editor, cost table.
6. **Providers (API Keys)** — per-provider key, model, base URL, Test connection.
7. **Privacy & Storage** — retention, encryption at rest, local-only apps, storage usage, delete all data.
8. **Diagnostics** — permission status, audio test (record 5 s from mic + system), logs export (redacted).

## 11. Onboarding flow

1. Welcome → what the app does + consent/legal notice (§5.10).
2. Permissions checklist (mic, system audio, notifications, optional screen recording/accessibility/calendar).
3. Choose processing: **Local only** / **Cloud (BYOK)** → if cloud, enter key(s) + Test connection.
4. Choose apps to watch — all default to **Auto-record**; switch any app to Ask or Never (e.g., WhatsApp → Never for personal calls).
5. Optional: download local Whisper model (shows size & progress).
6. Test call: play a sample sound + speak to verify both tracks capture.
7. Done → app lives in the menu bar.

## 12. Edge cases

| Case | Expected behaviour |
|---|---|
| Zoom/Teams open but no call | No recording (mic not in use) |
| User records a WhatsApp voice note (short mic use) | Ignored due to debounce |
| User mutes for 5 minutes | Session continues (grace + app keeps device open); if device closes, grace extends to 60 s when last-known state was "in call" |
| Two meeting apps active at once | Keep first; notify with "Switch to" option |
| Bluetooth headset switches mid-call | Recording continues; marker logged |
| Meeting app crashes | Session finalised after grace period; audio kept |
| Mac sleeps/lid closed during call | Finalise on sleep notification; mark "interrupted" |
| No internet with cloud provider selected | Queue job; retry with backoff; offer local fallback |
| Invalid/expired API key | Clear error, link to Providers settings; transcript kept |
| Browser meeting in background tab | Detected via mic usage + any matching tab title; if title unavailable, prompt "Browser is using mic — record?" |
| Very long meeting (4h+) | Chunked recording & map-reduce summary |
| Disk nearly full | Warn / safe stop (§7.4) |
| Permission revoked mid-session | Stop track gracefully, notify, keep what was captured |

## 14. Acceptance criteria (MVP)

1. Starting a Teams, Zoom, or WhatsApp desktop call **automatically starts recording, with no prompt**, within **debounce + 1 s**, with the first 10 s preserved by pre-roll, and a confirmation notification with Stop/Discard appears.
2. Opening Zoom/Teams **without** joining a call never triggers recording.
3. The recording contains both the user's voice (mic track) and remote participants (system track), and **does not** contain audio from other apps (e.g., Spotify playing simultaneously).
4. Ending the call stops recording within **grace period + 2 s**.
5. A 30-minute meeting produces a final transcript with "Me"/"Others" labels and timestamps; click-to-seek works.
6. With a valid key entered in Settings, a summary with TL;DR, decisions and action items is generated automatically; with an invalid key, a clear error appears and the transcript remains available.
7. API keys are retrievable only via Keychain; a grep of the app data folder, logs, and exports finds no key material.
8. Force-quitting the app mid-recording and relaunching offers recovery of all audio up to the last 30-second chunk.
9. Search for a word spoken in a past meeting returns that session and jumps to the timestamp.
10. Disabling WhatsApp in Detection settings prevents any WhatsApp call from being recorded.

## 15. Risks & open questions

| # | Risk / question | Mitigation / decision needed |
|---|---|---|
| R1 | Meeting apps' mic behaviour differs (some keep mic open outside calls, e.g., pre-join preview) | Per-app tuning in detection rules; secondary signals (window titles, audio output) |
| R2 | Process taps require macOS 14.2+/14.4+ | Set min OS 14.4; ScreenCaptureKit fallback |
| R3 | Mac App Store sandbox may block process taps / cross-app inspection | Ship notarized direct download first |
| R4 | Local diarization accuracy on mixed system audio | Offer cloud diarization providers; allow manual speaker correction |
| R5 | Legal exposure from recording without consent | Consent notice, reminders, visible indicators; user responsibility clause in EULA |
| R6 | Bengali / code-switched transcription quality | Evaluate Whisper large-v3/turbo vs cloud providers early |
| Q1 | Which Whisper model to bundle vs download on demand? | Spec assumes download on demand |
| Q2 | Should a future version support sharing with others / sync? | Not in scope; UUIDs keep the door open |
